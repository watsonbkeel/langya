# AI 行为设计规范

本项目有**两类 AI**，设计目标完全相反：

| AI | 目标 | 设计倾向 |
|---|---|---|
| 日军敌人 | 给玩家制造压力，但要可战胜 | 数量多、个体弱、行为可预判 |
| 中国军队队友 | 补足单人看不住三路的短板 | **能帮忙但不能抢戏** |

---

## 第一部分：日军敌人 AI

### 状态机

```
        ┌──────────┐
        │  Spawn   │  在刷新点生成
        └────┬─────┘
             ↓
        ┌──────────┐
   ┌───→│ Advance  │  沿路径点向上推进
   │    └────┬─────┘
   │         ↓ 进入射程 / 被击中
   │    ┌──────────┐
   │    │ Engage   │  停下射击
   │    └────┬─────┘
   │         ↓ 目标消失 / 压制解除
   └─────────┘
             ↓ HP ≤ 0
        ┌──────────┐
        │   Dead   │  永久移除，不复活
        └──────────┘
```

**关键**：敌人**没有撤退状态**。这是「日军不惜代价冲锋」的历史设定，也简化了 AI。

### 三种兵种

| 兵种 | HP | 速度 | 占比 | 行为特点 |
|---|---|---|---|---|
| 步枪兵 | 100 | 3.2 m/s | 55–90% | 交替跃进：前进 2 秒 → 停下射击 1.5 秒 |
| 轻机枪手 | 120 | 2.4 m/s | 10–20% | 找到掩体就架枪长时间压制，很少移动 |
| 突击兵 | 80 | 4.5 m/s | 0–25% | 不停顿直冲，只在极近距离射击 |

占比随波次变化，见 `shared/config/enemies.json`。

### 路径点导航（不做实时寻路）

**性能关键决策**：40 个敌人做 A* 实时寻路会吃满 CPU。用预设路径点。

```ts
// 每条路线是一串路径点
const ROUTES = {
  A: [ {x:0,z:0}, {x:2,z:20}, {x:-1,z:40}, {x:0,z:60} ],   // 正面陡坡
  B: [ ... ],                                                // 侧翼缓坡
  C: [ ... ],                                                // 背面绕行
};

// 敌人沿路径点前进，加随机偏移避免排队行军
const offset = {
  x: (Math.random() - 0.5) * 4,
  z: (Math.random() - 0.5) * 2,
};
```

**加偏移很重要**：否则 15 个敌人会走成一条直线，看起来很假，也让玩家一梭子扫一片。

### 目标选择

```
1. 若正在被某玩家射击 → 优先反击该玩家（60% 概率）
2. 否则选择视野内最近的友方目标（含 AI 队友）
3. 距离 > 180m 不开火
4. 距离 > 120m 伤害 × 0.6
```

**敌人会攻击 AI 队友**，这是队友会阵亡的原因，也让战场看起来是真的在打仗。

### 开火预警

```
敌人决定开火 → 播放枪口焰 → 延迟 0.35 秒 → 实际造成伤害
```

这 0.35 秒是给玩家的**反应窗口**：看到枪口焰可以蹲下或躲掩体。没有这个窗口，玩家会觉得「莫名其妙就掉血」。

### 四波难度递增

| 波次 | 兵力 | 精度 | 步枪/轻机枪/突击 |
|---|---|---|---|
| 一 | 30 | 55% | 90% / 10% / 0% |
| 二 | 50 | 65% | 70% / 20% / 10% |
| 三 | 60 | 72% | 65% / 20% / 15% |
| 四 | 60 | 80% | 55% / 20% / 25% |

**合计 200 人**。启动时必须校验总和。

### 滚动投放

```ts
// 不一次性生成，按小队分批
波次一：每 15 秒 10 人 × 3 队
波次二：每 12 秒 12 人 × 4~5 队
波次三：每 12 秒 15 人 × 4 队
波次四：每 10 秒 15 人 × 4 队

// 同屏存活上限 40，达上限暂缓投放
if (aliveEnemies >= MAX_ALIVE) return;
```

> **重要**：以「打满 200 人」为准。若因上限导致投放延后，允许 5:00 结束时仍有敌人未投放完，按实际歼敌计分。

## 第二部分：AI 队友

### ⚠️ 设计红线：队友是协防者，不是宠物，也不是代打

```
❌ 错误 1：队友跟着玩家跑（宠物式）
   → 结果：三条路还是只有玩家一个人的视野在管，等于没配队友

❌ 错误 2：队友太强，包办大部分击杀
   → 结果：玩家变成旁观者，毫无成就感

✅ 正确：队友各自驻守防区，独立作战，玩家仍是主力
```

### 布防机制

```
开局：4 名队友按路线分配
      单人模式默认：玩家在 A 路，队友 A×1 / B×2 / C×1

动态补位：玩家长时间（> 8 秒）停留在某路线
      → 该路线的队友调往其他路线
      → 保证三条路都有人看
```

```ts
// 补位逻辑示意
updateDeployment() {
  const playerRoute = this.detectPlayerRoute();
  const coverage = this.countAlliesPerRoute();

  // 玩家所在路线可以少放人
  const need = { A: 1, B: 1, C: 1 };
  need[playerRoute] = 0;

  // 把冗余的队友调往空缺路线
  for (const route of ROUTES) {
    if (coverage[route] < need[route]) {
      this.reassignNearestSpareAlly(route);
    }
  }
}
```

### 数值标定

| 属性 | 数值 | 与玩家对比 |
|---|---|---|
| HP | 100 | 相同 |
| 武器 | 中正式步枪（固定） | 玩家可切换 |
| 伤害 | 55 | 相同（同一把枪） |
| 射速 | 0.7 发/秒 | 玩家 0.9，队友更慢 |
| 命中率 | 55%（>120m 降至 35%） | 玩家取决于技术 |
| 反应延迟 | 0.6 秒 | 玩家更快 |
| 血包 | 1 个，HP<30% 自动用 | 玩家 2 个 |

### 队友不能做的事

| 限制 | 原因 |
|---|---|
| **不使用重机枪** | 重机枪是高价值资源，留给真人 |
| **不拾取空投血包** | 同上，空投只给真人 |
| **不切换武器** | 简化逻辑，也避免抢武器架 |
| **不参与 MVP 评选** | MVP 是给真人的荣誉 |

### 喊话系统（单人模式的核心信息补偿）

玩家看不住三条路 —— 这是设计上的**故意留白**，靠队友喊话来补。

```ts
// 触发条件
if (enemiesInMyRoute >= 5 && !recentlyCalledOut) {
  broadcast({
    type: 'ally_callout',
    allyId: this.id,
    routeId: this.route,
    text: `${this.heroName}：${ROUTE_NAME[this.route]}上来了！`
  });
  // HUD 对应路线指示器闪烁
}
```

**喊话文案**（用五壮士姓名，兼顾代入感与历史认知）：

| 场景 | 文案 |
|---|---|
| 路线敌人密集 | 「葛振林：西侧上来了！」 |
| 自己血量低 | 「宋学义：我这边顶不住了！」 |
| 击杀较多 | 「胡德林：这边稳住了！」 |
| 队友阵亡 | 「胡福才……牺牲了。」 |

**冷却**：同一队友喊话间隔 ≥ 8 秒，避免刷屏。

### 状态机

```
     ┌─────────┐
     │ Deploy  │  移动到分配的防守位
     └────┬────┘
          ↓ 到位
     ┌─────────┐
  ┌─→│ Guard   │  驻守，扫描防区
  │  └────┬────┘
  │       ↓ 发现敌人
  │  ┌─────────┐
  │  │ Engage  │  射击（0.6s 反应延迟）
  │  └────┬────┘
  │       ↓ 防区清空
  ├───────┘
  │       ↓ 收到重新部署指令
  │  ┌─────────┐
  └──│Reassign │  转移到新防区
     └─────────┘
          ↓ HP ≤ 0
     ┌─────────┐
     │  Dead   │  不复活
     └─────────┘
```

## 第三部分：难度校准（M2 必做）

**这是 AI 队友系统最大的风险点，必须实测。**

### 校准指标

| 指标 | 目标区间 | 超标处理 |
|---|---|---|
| 4 名队友合计歼敌占比 | **≤ 50%**（理想 40%） | 下调命中率或射速 |
| 队友平均存活时长 | ≥ 3 分钟 | 太低说明太弱，上调命中率 |
| 玩家歼敌数 | 应高于任一单个队友 | 否则玩家会有挫败感 |

### 校准方法

```bash
# 跑 10 局自动化模拟（玩家用固定策略脚本代打）
node tools/simulate-match.js --runs 10 --output stats.json

# 输出应包含
{
  "avgPlayerKills": 48,
  "avgAllyKillsTotal": 76,       # 4 个队友合计
  "allyKillRatio": 0.41,          # ← 关键指标，应 ≤ 0.5
  "avgAllySurvivalSec": 218
}
```

### 调参优先级

若队友太强，按此顺序调整：

```
1. 降低命中率（55% → 45%）        ← 首选，影响最直接
2. 降低射速（0.7 → 0.55 发/秒）
3. 增加反应延迟（0.6s → 0.9s）
4. 减少初始血包（1 → 0）           ← 最后手段，会让队友死太快
```

**不要**通过降低伤害来削弱队友 —— 伤害和玩家用同一把枪，改了会造成认知混乱。

## 性能约束

44 个 AI 实体（40 敌 + 4 友）不能每 tick 全量决策。

```ts
// 分 4 组轮转，每个 AI 实际 5Hz 决策
const group = tick % 4;
for (let i = group; i < entities.length; i += 4) {
  entities[i].think(dt * 4);
}
```

**移动插值仍每 tick 执行**，只有决策降频。玩家感知不到。

**其他优化**：
- 视野检测用距离 + 角度判断，不做完整射线检测
- 路径点导航预计算，不做运行时寻路
- 目标选择用空间网格加速，不做 O(n²) 遍历

## 检查清单

### 敌人 AI
- [ ] 四波总数恰好 200，启动时校验
- [ ] 三条路线按 50/30/20 分配
- [ ] 敌人有 0.35 秒开火预警
- [ ] 敌人无血包、无治疗、死亡永久移除
- [ ] 敌人会攻击 AI 队友，不只盯着玩家
- [ ] 路径点加随机偏移，不排队行军
- [ ] 同屏上限 40 生效

### 队友 AI
- [ ] 队友分守路线，不跟随玩家
- [ ] 玩家换位时队友动态补位
- [ ] 队友不用重机枪、不抢空投
- [ ] 队友低血量自动用血包（仅 1 个）
- [ ] 喊话系统生效，有冷却，用五壮士姓名
- [ ] 队友阵亡后不复活
- [ ] **实测队友合计歼敌 ≤ 50%**

### 性能
- [ ] AI 分帧计算已实现
- [ ] 44 个实体下 tick 耗时 < 15ms
