# 视觉评审后续开发安排

> 基于 `REVIEW-CLIENT-VISUAL.md` 的建议和当前 M3 实际代码整理。
> 评审文档是参考意见，不是需求变更；最终仍以 `AGENTS.md`、
> `docs/PRD.md` 和 `docs/COLLAB.md` 为准。

## 1. 本轮决定

M3 的试玩对象是 watson 本人，因此不在部署前插入完整的
1–2 天视觉改造，以免延误“策划 → 验证 → 优化 → 再验证”的核心节奏。

在交给 Debian 部署 M3 之前，Mac 先完成一组低风险、高收益的
“交接前修整”：

1. 去掉默认 HUD 中的里程碑代号、架构术语、延迟和裁决毫秒数。
2. 修正错别字，把帮助文字改为限时引导，加强准心可读性。
3. 启用已有的 `entityPositionSmoothing`，去掉 20Hz 快照中反复创建
   tween 和 `Vec3` 的热路径分配。
4. 自动化状态只写 `data-langyashan-m3`，不再每帧重复序列化
   M1/M2 副本。
5. 保持 M3 已完成的协议、物资、重机枪、倒计时和战报功能不变。

## 2. 后续阶段与顺序

| 阶段 | 负责方 | 内容 | 进入条件 | 完成判据 |
|---|---|---|---|---|
| A. M3 交接前修整 | Mac | HUD 文案、准心、限时引导、实体指数平滑、测试状态去重 | M3 客户端已能构建 | 类型、配置、Creator 构建通过；默认 HUD 不暴露开发术语 |
| B. M3 统一部署 | Debian | 拉取 Mac 提交、发布 M3 构建和权威服务 | A 完成并传送构建包 | PM2/Nginx 在线，M0–M3 自测通过 |
| C. M3 真实整局验收 | Mac + Debian | 浏览器真实等待 5 分钟，核对四波、200 人、物资、重机枪和战报 | B 完成 | 结算页展示 5 席；投放 200/200；无页面异常；实测帧率有记录 |
| D. watson 试玩节点 | watson | 评估射击手感、难度、信息压力和重机枪 | C 通过 | 收到明确试玩反馈；在此之前不进 M4 |
| E. 视觉基线 VB0 | Mac 主力 | 光照/天空/雾、HUD 分区自适应、倒地淡出、部署期叙事 | D 完成且 watson 确认采用 | 16:9、16:10、4:3 不错位；地形有明暗层次；PC ≥ 50 FPS |
| F. M4 美术接入 | Mac | 素材管线、Billboard、武器立绘、真实音效 | D 与必要的 E 完成 | M4 全部验收项通过，资源 < 25 MB |

## 3. 评审项的取舍

| 评审项 | 处理 | 阶段 | 说明 |
|---|---|---|---|
| P0-1 光照/天空/雾 | 采纳，但不阻塞 M3 首次玩法验证 | VB0 | 需在 M4 调立绘前建好视觉基线 |
| P0-1b 夜色到清晨过场 | 候选，需 watson 明确确认 | VB0 | 只做叙事与光照变化，不增加地雷玩法 |
| P0-2 HUD 调试文案 | 立即采纳 | A | `?debug=1` 时才显示延迟；默认只留玩家文案 |
| P0-3 布局自适应 | 采纳 | VB0 | 改为边缘分区 + Widget，并同步 Canvas 设计分辨率 |
| P1-1 `facingYaw` | 候选协议提案 | M3 后 / M4 前 | 不在当前协议已稳定后突袭修改 `shared/**` |
| P1-2 实体插值 | 立即采纳 | A | 用 `update(dt)` 指数平滑，复用向量，不在 20Hz 快照创建 tween |
| P1-3 死亡倒地淡出 | 采纳 | VB0 | 先打通标准材质 alpha 管线，再接 M4 Billboard |
| P1-4 枪口预警 | 部分已做，后续升级 | M4 | 当前橙色块 + HUD 路线⚠保留，M4 换粒子/面片 |
| P1-5 真实音效 | 采纳 | M4 | 先合并音频管理，再引入真实音频；不在 M3 临时加来源不明素材 |
| P1-6 武器曲线 | 采纳 | M4 | 拆分像素/角度配置，与武器立绘同调 |
| P2-1/3 页面标题/背景 | 立即采纳 | A | 通过 Cocos Web 构建模板固化，构建产物仍不入库 |
| P2-4/7 准心/错别字 | 立即采纳 | A | 先画深色粗线，再画白色细线 |
| P2-6 `setTimeout` | 延后 | VB0 | 当前只用于短时表现，不阻塞 M3；VB0 统一调度 |
| P2-8/9 图形化血条/威胁 | 延后 | M4 | 与 UI 视觉资产一起处理 |
| P2-10 测试状态重复 | 立即采纳 | A | 只保留当前里程碑属性 |
| P2-11 类名重构 | 延后 | VB0 | 需单独小提交，不与 M3 联调叠加 |
| P2-12 resize | 并入布局自适应 | VB0 | 覆盖窗口缩放与全屏切换 |

## 4. 双端交接清单

### Mac 交付 Debian

- `origin/main` 上的 Mac 提交号。
- Taildrop 构建包名、大小与发送结果。
- `npx tsc --noEmit`、配置镜像、Creator 构建结果。
- 尚未验证的边界：M3 真实服务、5 分钟整局、重机枪和战报。

### Debian 回传 Mac

- PM2/Nginx 发布完成且 M0–M3 自测通过。
- 可访问的 Tailscale 地址。
- 服务端实际启动提交和日志时间。
- 浏览器验收期间的服务日志/战报对应结果。

## 5. M3 验收后停止线

M3 两端验收通过后，按 `docs/MILESTONES.md` 立即停止功能开发，
由 Debian 输出试玩地址、操作说明和已知问题，等待 watson 反馈。
未经反馈，不进入 VB0 或 M4。
